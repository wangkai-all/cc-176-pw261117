# 订单窗口指标 · 增量更新控制台

本地应用，无第三方运行依赖：Python 标准库 HTTP 服务 + SQLite + 原生 HTML/CSS/JS。
支持导入新订单、撤销旧订单、更正历史金额；每次变更先解释影响范围，再只重算必要的时间锚点，
并以单个事务原子发布。

## 快速开始

```bash
cd /workspace
python3 -m app.server            # 默认 http://127.0.0.1:8765，自动打开浏览器
```

- 首次启动自动写入 4 位客户、16 笔订单的样例，并物化所有指标锚点。
- 数据库默认 `data/metrics.db`，可用 `--db /tmp/foo.db` 覆盖，`--port`、`--host`、`--no-browser` 同理。
- 重置样例：页面右上角「重置样例」，或 `POST /api/reset`。

```bash
python3 -m unittest discover -s tests -v      # 29 个测试
```

## 指标口径

| 指标 | 定义 |
|---|---|
| 滚动七日金额 | 闭区间 `[T−7天, T]` 内**有效**订单金额之和；两端都计入，`T` 当刻与恰好 7 天前的订单都算。按实际时间而非固定行数。 |
| 累计金额 | `occurred_at ≤ T` 的全部有效订单之和。 |
| 最近三笔均值 | `occurred_at ≤ T` 的有效订单按 `(occurred_at, order_id)` 升序，取最后 3 笔，以 `合计 / 笔数` 计算，接口返回精确合计与笔数，页面仅在展示时舍入到分（不做中间舍入）；同一时刻按订单号字典序，订单号大者视为更晚，顺序稳定。不足 3 笔时按实际笔数求均值。 |
| 撤销 | 撤销订单保留其事件时刻作为时间轴锚点，但不计入任何金额；撤销会改变该时刻之后每个锚点的累计金额与最近三笔构成。 |
| 时间轴 | 客户时间轴 = 该客户全部事件时刻（含仅撤销订单的时刻），每个锚点物化一行指标。 |

所有时间在 API 与数据库中是整数 epoch 毫秒（UTC）；金额以整数分存储，元 ↔ 分使用 Decimal 精确换算。

## 增量重算模型

对一次批次：

1. **校验整批**，收集所有错误（订单不存在、重复订单号、已撤销再操作、负金额、超过两位小数等），任何一条不合法都拒绝整批。
2. **在事务内计算**新旧完整订单集，得出每个受影响客户：
   - 滚动七日只可能在每个变更订单的 `[t, t+7天]` 内变化，多个窗口重叠/相邻时合并（`metrics.merged_ranges`）；
   - 累计金额与最近三笔自最早变更时刻起持续受影响；
   - 只重算 `≥ 最早变更时刻` 的既有锚点，并加上新导入订单产生的新锚点；更早锚点不重算，也不写入。
   - 一批多条相邻操作只做一次重算遍历，影响区间合并为连续段。
3. **预览**完全只读，不写任何表。
4. **提交**在单个 `BEGIN IMMEDIATE` 事务内写订单、指标缓存、批次日志、逐锚点重算日志和审计事件；任一步失败整体回滚，因此不会出现「一部分指标已发布」的状态。可用页面「模拟提交中断」验证。

页面与 API 会解释：受影响客户、滚动窗口区间、重算区间、每个锚点的修改前后值、窗口内订单构成变化、未重算锚点数。

## 页面功能

- KPI 卡片、口径定义、客户指标表（可切换评估时刻 T、按客户查看窗口内订单 / 最近三笔 / 全部订单）。
- 批次编辑器：5 个样例一键填充，JSON 直接编辑；预览后才可提交。
- 影响范围：文字解释 + 每客户影响区间条（滚动窗口影响 / 实际重算区间）+ 锚点前后对照表（默认只看变化，可展开全部）。
- 批次历史：每个已提交批次的订单变更明细与完整重算日志。
- 缓存校验：从订单事实重算所有锚点并与缓存逐项比对。
- 浅色/深色自动适配，窄屏单列布局，键盘可操作，表格数值使用等宽数字。

## API

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/state?as_of=ISO` | 客户指标、摘要、评测时刻、批次历史 |
| GET | `/api/customers/{id}?as_of=ISO` | 单客户指标、窗口构成、全部订单、时间轴 |
| GET | `/api/batches/{id}` | 批次请求、变更明细、逐锚点重算日志 |
| GET | `/api/demo` | 样例批次目录 |
| GET | `/api/verify` | 用订单事实重算并对比缓存 |
| GET | `/api/audit` | 审计事件 |
| POST | `/api/preview` | 只读预演，返回影响解释与前后对照 |
| POST | `/api/commit` | 原子提交；可带 `simulate_failure: true` 演示回滚 |
| POST | `/api/reset` | 重置为初始样例 |

### 批次格式

```json
{
  "operations": [
    {"op": "import",  "order_id": "O-1007", "customer_id": "C-1001",
     "customer_name": "新客户（仅首单需要）", "amount": "310.00",
     "occurred_at": "2026-11-09T09:00:00Z"},
    {"op": "void",    "order_id": "O-1001"},
    {"op": "correct", "order_id": "O-1002", "amount": "1000.00"}
  ]
}
```

- `amount` 为元：字符串或数字，最多两位小数，不接受浮点误差（内部用 Decimal）。
- 同一批次内同一订单号只能出现一次；单批最多 500 条。

## 样例

`samples/` 下的 JSON 可直接粘贴到页面，或命令行执行：

```bash
python3 samples/run_batch.py samples/late-correction.json
python3 samples/run_batch.py samples/void-old.json --commit
python3 samples/run_batch.py samples/void-old.json --commit --simulate-failure
```

| 文件 | 场景 |
|---|---|
| `same-instant.json` | 在既有订单同一时刻插入新订单（同时间订单排序与窗口边界） |
| `late-correction.json` | 更正 11-03 的历史金额（迟到更正，影响后续所有锚点） |
| `void-old.json` | 撤销最早订单（累计与最近三笔一路延伸到最新） |
| `cross-window-void.json` | 撤销后跨 7 天窗口导入替代订单（窗口清空再回填） |
| `adjacent-batch.json` | 一次更正三笔相邻订单（影响区间合并） |

种子数据本身也覆盖边界：`C-1001` 有两笔同刻订单（`O-1004`/`O-1005`）；
`C-1002` 的 `O-2003` 距最新锚点恰好 7 天（闭区间边界）；`C-1003` 订单间隔超过 7 天（窗口清空）；
`C-1004` 用于验证未受影响客户不被重算。

## 目录结构

```

app/db.py          SQLite 持久化、整批校验、影响预测、原子提交、读接口
app/server.py      标准库 HTTP 服务与 JSON API
app/seed.py        种子数据与 5 个样例批次
web/               页面（index.html / styles.css / app.js，无依赖）
samples/           样例批次 JSON 与命令行执行脚本
tests/             窗口语义、影响范围、原子性、API 测试
```
